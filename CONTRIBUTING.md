# Contributing

DeskBridge is a thin, tested product layer around the **unmodified** Deskflow
engine. Keep it that way.

## Hard rules

1. **Never modify the engine.** `engine/` binaries are downloaded from the
   pinned upstream release and verified against `ci/manifest.json`
   (sha256 + size). To move the engine version: bump the pin, re-verify the
   digest, and re-run the verification matrix in `docs/TESTING.md`.
2. **`src/deskbridge` stays stdlib-only** (Python 3.9+): it must run on a
   plain Fedora desktop without pip installs.
3. **`tools/DeskBridge.ps1` stays PowerShell 5.1 compatible** (no PS7-only
   cmdlets) and must never hard-code machine-specific addresses (the
   firewall scope is the `-ClientIP` parameter).
4. **State is user-scoped.** Nothing under `/etc` on Linux, no service
   required for sharing. Certificates and trust databases are never
   regenerated by product commands (`setup`, `repair` keep them).
5. **Docs are a claim.** Every behavior claimed in README/docs must have a
   row in `docs/TESTING.md` saying how it was verified. Update both together.

## Running the tests

No root and no display required:

```bash
python3 tests/test_deskbridge.py        # app core (17 tests)
python3 tests/test_client_config.py     # shipped client INI
python3 tests/test_server_config.py     # shipped server INI
python3 tests/test_server_ini.py        # shipped screen map
```

`tests/run-local-smoke.sh` needs an X/Wayland session (loopback engine test).

## Building and releasing

```bash
tests/fetch-engine.sh              # download pinned engine into engine/
python3 ci/download_manifest.py stage
python3 ci/package_bundles.py stage # builds zips + SHA256SUMS + RELEASE.md,
                                     # validates actual ZIP contents
```

Releases are tagged `vX.Y.Z[-rcN]` on `main`. Where CI is available
`release.yml` builds and publishes; otherwise build locally with the same
`ci/` scripts and publish via `gh release`, then re-download the assets and
verify `SHA256SUMS` before announcing.
